# AGENTS.md — wabot-go (Flora GO)

WhatsApp bot in Go (`hypermeow` fork of `whatsmeow`, pure-Go `modernc.org/sqlite`, no cgo). Module `wabot-go`, Go 1.26+. Entry: `main.go`. No CI, no lint/typecheck config, no `opencode.json`.

## Run / verify

- `go run .` — but there is **no dotenv loader** (only `os.Getenv`, no godotenv/viper). The `.env` file is never auto-read; export vars in the shell first (see `scripts/test-env.ps1` pattern: `$env:OWNER_NUMBERS=...` then `go run .`).
- `OWNER_NUMBERS` (comma-separated digits) is mandatory — empty panics at startup. `LOGIN_METHOD` must be `qr` or `pairing`, else panic. `PHONE_NUMBER` required for pairing.
- `go build ./...` · `go vet ./...` (clean) · `go test ./...`
- Only `plugins` has tests: `go test ./plugins/ -v`; single test: `go test ./plugins/ -run TestNoCommandAliasCollision -v`
- `ffmpeg` must be in PATH wherever the bot runs (stickers, thumbnails, transcode fail otherwise).

## Add a command (plugins/)

Self-registration — never edit `registry.go`. New file in `plugins/` with `init() { registerPlugin(RegisterX) }`; `Category` must be a `CategoryXxx` const (free strings spawn ghost menu groups); `Hidden: true` + `CategoryHidden` to hide from `.menu`. Aliases share the command map and **silently overwrite** — `go test ./plugins/` catches collisions. `.tt` belongs to `tiktok` (regression-tested; tictactoe uses `.ttt`/`.tc`).

## Add an AI tool (internal/ai/)

Same pattern, different registry: put pure tools in `internal/ai/tools/native/`, WhatsApp-access tools in `internal/ai/tools/bridge/`, register via `ai.RegisterTool(...)` in `init()` — then add the **side-effect import in `main.go`**, or the tool silently never registers.

## AI provider call (internal/ai/openai_adapter.go)

`Generate` selalu mencoba **streaming** dulu (`stream:true` + `stream_options.include_usage` + SSE): gateway ciora mengalirkan byte pertama dalam ±0,2 dtk, sedangkan non-streaming baru menjawab setelah selesai — Cloudflare memutus yang diam >100 dtk dengan `524`. Jangan hapus jalur streaming atau menaikkan `AI_REQUEST_TIMEOUT` sebagai "perbaikan" 524 (batasnya di gateway, bukan di bot). Jalur streaming memakai `streamHTTPClient` dengan `ResponseHeaderTimeout` (`streamHeaderTimeout`, 25 dtk) supaya gateway yang tersangkut gagal cepat lalu retry sekali (error "timeout awaiting response headers" = timeout biasa); **jangan** pasang batas itu di `HTTPClient` non-streaming, karena generasi normal bisa butuh puluhan detik sebelum header. Fallback otomatis: gateway membalas JSON biasa → dibaca sebagai JSON; 400 menyebut `stream` atau stream kosong → satu kali non-streaming; 400 menyebut `tools` → ulang tanpa tools. `max_tokens` dan `reasoning_effort` **diabaikan** gateway ciora (terbukti dari uji), jadi jangan dipakai untuk mengatur panjang/berpikir. Error status ≥400 non-JSON dilaporkan sebagai `status HTTP <kode>` + durasi + payload KB + cuplikan body (bukan "gagal parse"); 5xx dianggap transient, tapi `524` sengaja **tidak** di-retry (`isGatewayTimeoutError`).

## Generate & edit gambar (.seedream / internal/arena)

Owner-only `.seedream` (alias `.sd`) membuat gambar **dan mengedit foto**: satu command, tanpa subcommand generate/edit — dispatch di `plugins/seedream.go` memilih edit kalau pesan memuat gambar (dilampirkan/di-reply), selain itu generate; `cookie` satu-satunya subcommand eksplisit (`.seedream cookie <cookie>`, tanpa argumen = status), dan `.seedream` tanpa argumen menampilkan blok petunjuk `*Seedream*` (`Opt`). Command lama (`sedit`, `scookie`, `s5`, `imagine`, `simagine`) sudah dihapus, jangan dihidupkan lagi. Kedua jalur memakai akun arena.ai owner dengan **Chrome panel**, bukan solver captcha pihak ketiga: endpoint `create-evaluation` menuntut token reCAPTCHA Enterprise v3 (`chat_submit`) yang hanya bisa dibuat JS halaman arena.ai. Alur: buka `/image/direct` di tab CDP → suntik cookie sesi → `grecaptcha.enterprise.execute` → `fetch` → stream berisi `{"type":"image","image":"<url>"}` → unduh. Model diresolusi dari `nextjs-api/model-catalog` (cache 24 jam). Sesi login ada di `data/arena-cookie.txt` (tulis lewat `.seedream cookie`, atomik, cookie tak pernah di-echo), profil Chrome di `arena-profile/` (gitignored). **Cookie disimpan-balik otomatis**: setelah generate sukses `browser.saveCookies` memanggil CDP `Storage.getCookies` (termasuk HttpOnly), memfilter domain `arena.ai`/`*.arena.ai`, mengurutkan nama (fingerprint stabil), dan menulis ulang lewat `WriteCookie` hanya bila berubah + masih memuat `arena-auth-prod-v1` (guard agar sesi baik tidak tertimpa set anonim); `b.cookieFP` ikut diperbarui supaya Chrome tidak restart. Jangan panggil `saveCookies` di `stop()` — stop juga dipakai saat `.seedream cookie` baru membuat fingerprint berbeda, dan menyimpan di sana akan menimpa cookie baru dengan yang lama. `.seedream cookie` tanpa argumen memakai `CookieStatusOf` (`cookie_status.go`) yang meng-decode sesi Supabase (`base64-` + JSON chunked, fallback klaim `exp` JWT) tanpa menampilkan token. **Chrome headless ditolak reCAPTCHA** (403 `recaptcha validation failed`) walau UA (`HeadlessChrome`), Client Hints, ukuran layar 800x600, dan WebGL sudah disamarkan — Chrome headed di mesin yang sama langsung 200. Karena itu `startDisplay` menyalakan **Xvfb** (`:99+`, `1280x900x24`) bila binary-nya ada, lalu Chrome dijalankan tanpa flag headless; tanpa Xvfb jatuh ke `--headless=new` (jalan, tapi reCAPTCHA sering menolak). Karena panel 1,6GB/1 core: generate diserialkan (`genMu`), peluncuran ditolak kalau sisa memori cgroup <500MB, Chrome+Xvfb mati sendiri setelah `ARENA_CHROME_IDLE_SECONDS`. **Idle-stopper tidak boleh mematikan Chrome yang sedang melayani permintaan**: `Generate` memanggil `beginRequest`/`endRequest` (`browser.busy`) dan `stopWhenIdle` melewati stop selama `busy>0` — tanpa itu jalur edit (attach + unggah 4MB + generate) yang melewati 150 detik dibunuh di tengah `Runtime.evaluate` dan owner melihat "DevTools terputus" (bukan salah arena.ai); `idleExpired` dipisah agar bisa diuji. Diagnostik: `cdpClient.fail` menyimpan error/close-code websocket (1001 = ditutup bot, 1006 = proses mati), satu goroutine pemantau `cmd.Wait` mencatat exit code (juga mencegah zombie), dan `browser.failureHint` menempelkan keadaan Chrome + sisa memori cgroup ke pesan gagal; `dropBrowser` membuang tab mati supaya perintah berikutnya menyalakan Chrome baru (tidak auto-retry, agar kuota tidak terpakai dua kali). Uji: `ARENA_SMOKE=1` (wiring + fingerprint) / `=2` (generate via Chrome) / `=3` (jalur `GenerateImage` penuh) / `=4` (jalur edit: `Generate` dengan gambar referensi) / `=5` (transport CDP dengan payload 4 MB + base64 5 MB, bentuk yang dikirim jalur edit; tanpa kuota). Jangan jadikan `waitPageReady` menunggu `readyState=="complete"` — arena.ai berhenti di `interactive` selamanya, dan jangan pula menggagalkan peluncuran karena `readyState` (sejak Xvfb, halaman bisa tersangkut `loading` di panel 1 core; kegagalan di situ melempar bot ke headless yang selalu ditolak reCAPTCHA). `waitReadyFor` menerima `interactive` **atau** keberadaan `grecaptcha`, dan saat batas waktu habis hanya mencatat diagnostik (`pageDiagnostics`: title/body/scripts/resources — penanda challenge Cloudflare) lalu lanjut. Chrome headed memakai `headedFlags()`: `--disable-gpu` + flag anti-throttling/occlusion, karena Xvfb tanpa window manager membuat Chrome menganggap jendelanya tersembunyi. `wakeCaptcha` memuat ulang halaman sekali kalau `grecaptcha` belum ada. JSON di template JS **wajib** lewat `jsQuote` (nilai mentah = SyntaxError).
Output gambar: `seedreamSend` **wajib** me-reply perintah user (`ContextInfo` StanzaID/Participant/QuotedMessage pada `ImageMessage`), caption dari `seedreamCaption` berformat `Generate With <model>` / `Edit With <model>` + baris `> prompt` (satu baris, dipotong `…` di bawah 1000 rune) dan **tidak boleh** menyebut arena.ai karena terlihat publik. Sebelum generate, `store.SendText` mengirim `seedreamWaitText` (tanpa emoji, **tanpa quote** — jangan diganti `ReplyText`, nanti chat penuh balasan).

Jalur edit (`seedreamEdit` di `plugins/seedream_edit.go`) memakai `arena.Generate(ctx, Request{Prompt, Images, Model})`: gambar referensi **wajib** lewat storage arena.ai (R2) — server menolak `data:` URL maupun URL publik sembarang dengan `400 {"error":"Invalid content"}`, sudah diuji di browser owner. Karena itu skrip halaman melakukan rantai unggah sendiri: panen id Server Action `generateUploadUrl` + `getSignedUrl` dari bundle yang dimuat halaman (regex `([0-9a-f]{40,})"[^)]{0,240}"generateUploadUrl"`, di-cache di `window.__arenaActions` dan diulang sekali kalau basi), POST `Next-Action` + `Content-Type: text/plain` body `JSON.stringify(args)` **selalu ke `location.origin + '/image/direct'`** (setelah generate, app bisa pindah ke `/c/<uuid>`), PUT byte ke presigned R2, lalu ambil `{name, contentType, url}` dari signed URL. Sebelum unggah, skrip memanggil `checkSession()` (`/api/me` → 401 = sesi mati) dan melempar error berawalan `auth:` yang dipetakan ke `ErrCookieRejected`; ini perlu karena action unggah membalas `{"success":false,"error":"Failed to generate upload url"}` untuk sesi anonim — pesan yang menyesatkan. Batas 1 gambar / 4 MB (`maxReferenceCount`, `maxReferenceBytes` di `arena.go`) karena base64 ikut masuk ekspresi `Runtime.evaluate`. Foto disiapkan `seditPrepareImage`: JPEG ≤4 MB & sisi ≤1600 dilewatkan apa adanya, PNG/GIF di-decode stdlib lalu di-encode JPEG di atas latar putih, webp/besar lewat `runFfmpegConvert` ke PNG 1600 lalu JPEG. Kuota/jeda/backoff jalur edit **berbagi** penghitung dengan `.seedream` (`seedreamBudget`). Kalau unggah gagal, pesan ke owner sengaja memuat potongan balasan Server Action (±240 char) + tahapnya (`uploadUrl/key tidak ada`, `storage menolak`, `signed URL tidak ada`) — detail itu owner-only dan tidak memuat cookie, jadi jangan diganti jadi pesan generik saat men-debug. Model edit default ikut `ARENA_MODEL`, bisa ditimpa `ARENA_EDIT_MODEL`; semua model gambar arena hanya mengeluarkan **1:1**.

## React Channel WhatsApp (.rch, internal/reactionwa)

Owner-only `.rch <link pesan> <emoji>` mengirim reaksi ke pesan WhatsApp Channel lewat situs `auto.reactionwa.online`, tanpa apikey. Jalur apikey Rin (`apiii-xrina.my.id`, `internal/rch`, `Get/SetRCHAPIKey`, `.rch apikey`) sudah **dihapus** — jangan dihidupkan lagi. Login Google cukup **sekali** di browser owner: `.rch login <refresh token>` menyimpan refresh token Firebase ke `data/rwa-token.txt` (atomik, 0600, tidak pernah di-echo; jangan taruh di `bot_settings`/`.env`), lalu bot mencetak access token sendiri via `securetoken.googleapis.com` (`Origin`/`Referer` situs **wajib**, tanpa itu 403 "Requests from referer <empty> are blocked") dan menyimpannya di memori sampai ±2 menit sebelum kedaluwarsa. Refresh token hasil rotasi server disimpan-balik otomatis. Captcha Cloudflare Turnstile **benar-benar diverifikasi** server, jadi tidak ada jalur HTTP murni: `internal/reactionwa/browser.go` menyalakan Chrome (+Xvfb di panel) untuk membuka `/Free/` **tanpa login**, memanggil `turnstile.getResponse()` (fallback `execute`), lalu mematikan Chrome lagi. Token Turnstile di-cache 4 menit (server menerima token yang sama berulang dalam masa berlakunya) supaya command beruntun tidak relaunch Chrome; captcha yang ditolak memicu satu percobaan ulang dengan token baru (`Invalidate`). Profil Chrome di `rwa-profile/` (gitignored) agar cookie clearance bertahan; peluncuran ditolak bila sisa memori cgroup <350 MB. Link wajib bentuk link **pesan** (`/channel/<id>/<nomor>`), query/hash/trailing slash dibuang sebelum kirim; maksimal 5 emoji (dipisah spasi/koma; emoji ZWJ tidak boleh dipecah). Server juga tidak memverifikasi `x-req-sig` (HMAC `RW_SECURE_SALT_v9#82d!`), tapi tetap dikirim agar request identik dengan aslinya. Error dipetakan ke `ErrNoToken`/`ErrTokenRejected`/`ErrCaptcha`/`ErrLimit`/`ErrLink`/`ErrBrowser` lalu diterjemahkan `rchErrorText`. `RWA_API_URL`, `RWA_CHROME_PATH`, `RWA_XVFB_PATH`, `RWA_HEADED=0` bisa menimpa default (dipakai tes/debug). Pengiriman async: pesan tunggu tanpa emoji + quote (`store.SendText`), hasil me-reply perintah. Hasil sukses menampilkan pesan server ("masuk antrean"), `key_id` tugas, dan poin VIP bila ada. **Kuota gratis ditegakkan server: 1×/24 jam per akun/IP** (pesan `Limit harian gratis telah habis (1x/hari)`), jadi kegagalan `ErrLimit` bukan bug bot; akun yang punya paket VIP pun tetap kena batas ini di endpoint reaksi.

## Aset kartu .menu (.thumbnail / .favicon, internal/messaging/linkcard.go)

`.thumbnail`/`.favicon` (owner, `plugins/menucard.go`) punya **dua bentuk nilai** di `bot_settings`: gambar tersimpan (`menu_thumb_blob`/`menu_favicon_blob`, base64) dan URL (`menu_thumb_url`/`menu_favicon_url`). Blob **menang** atas URL; menyimpan yang satu menghapus yang lain supaya sumber tidak ambigu, dan `reset` menghapus keduanya (kembali ke `.env`). Jalur gambar (kirim/reply, pola `menuAssetImage` — bukan `extractStickerMedia` karena pesan error stiker membingungkan) adalah jalur utama: `LinkCard.ThumbBytes` dipakai apa adanya sehingga `.menu` **tidak menyentuh jaringan sama sekali**; batas simpan 4 MB (`maxMenuAssetBytes`) dan wajib lolos `image.DecodeConfig`. Jalur URL (`LinkCard.ThumbURL`) menerima **daftar** dipisah koma/spasi yang dicoba berurutan (`splitThumbSources`), tiap URL diunduh maksimal 2 percobaan × 7 dtk (`thumbAttempts`/`thumbAttemptTimeout`, hanya untuk timeout/jaringan/5xx/429 — 4xx dan non-image = `thumbPermanentError`, tidak diulang), dan byte yang pernah sukses disimpan di `data/thumb-cache/<sha256(url)>.img` (atomik, bukan `wabot-tmp` karena harus tahan restart) sehingga host yang sedang mati hanya membuat bot memakai salinan lama, bukan kehilangan thumbnail. Semua kegagalan tetap fail-soft: kartu teks terkirim tanpa gambar dan hanya tercatat di console. Jangan hapus cache disk itu sebagai "file tak terpakai" — itu jaring pengaman saat catbox/GitHub down. Upload hasil normalisasi di-cache memori 6 jam dengan kunci `url:<url>` / `blob:<sha256>`.

## Kartu hasil Shazam (.shazam, plugins/shazam.go)

`.shazam` (alias `.find`/`.findmusic`) **hanya mendeteksi lagu**: reply VN/audio/video/dokumen → `external.RecognizeShazam`. Jalur teks lama (`.shazam search|cari`, `.shazam track <id>`, pick nomor 1-5, `.shazam unduh|dl`, dan kata polos "unduh") sudah **dihapus** bersama `SearchShazam`/`GetShazamTrack` di `internal/external/shazam.go`, `shPending`, dan guard `shNewerThanSpotify`/`shNewerThanLrc` — jangan dihidupkan lagi. Kartu hasil dikirim sebagai bubble `messaging.SendNativeFlow` (bukan gambar+caption): **ada track Spotify** → `quick_reply` "Unduh" ber-id `shazam:dl:<trackID Spotify>` (track ID ditanam di id, jadi **tanpa pending/TTL**; tap mendarat sebagai `TemplateButtonReplyMessage.SelectedID`, ditangani `CheckShazamButtonTap` → `shazamDoDownloadUnduh` → `downloadSpotifyAndSend`); **tanpa track** → `cta_url` "Buka Spotify" ke `https://open.spotify.com/search/<judul artis>` (`shazamSpotifySearchURL`, `url.PathEscape` = satu segmen path). Caption (`shazamTrackCaption`) sengaja **tanpa** link Spotify dan tanpa instruksi manual — link diwakili tombol. Cover dikirim sebagai **header gambar sungguhan**: unduh cover berlapis (`external.DownloadBytes` → `external.DownloadBytesIPv4` yang memaksa `tcp4` karena CDN Apple memutus transfer IPv6 di tengah body dari jaringan owner → cover Spotify via oEmbed `https://open.spotify.com/oembed?url=…` sebagai cadangan) → `messaging.HeaderJPEG` (decode JPEG/PNG/GIF/WebP → skala sisi terpanjang ≤640 → JPEG baseline q85; cover CDN bisa progressive/PNG/WebP) → `messaging.UploadImageMessage` (upload `MediaImage` → `ImageMessage` lengkap dengan URL/DirectPath/MediaKey/sha/length/dimensi + `JPEGThumbnail` inline) → `NFText.HeaderImage`, yang dirakit `messaging.NativeFlow` jadi `Header_ImageMessage` + `hasMediaAttachment`. **Jangan** kembali memakai `NFText.Thumb` (`Header.JPEGThumbnail`) untuk kartu bergambar: field itu hanya bitmap pratinjau kecil, klien mengabaikannya sehingga header tampak kosong (body + tombol tetap terkirim) — itu bug yang sudah dibuktikan di HP owner. Karena itu `shazamSendTrack` fail-soft **tetap satu bubble**: upload/gambar gagal → bubble teks + tombol yang sama; bubble gagal total → teks biasa (tidak boleh jadi dua pesan terpisah). Bentuk ini **terbukti tampil** di HP owner (uji live Okt 2026: cover Apple diunduh via IPv4 → dinormalkan → header muncul di bubble yang sama dengan tombol), jadi jangan kembali ke `JPEGThumbnail` atau memecahnya jadi dua pesan. `pdfTapID` sudah di-rename `nativeFlowTapID` (dipakai pdfmerge/jpgpdf juga) — pakai nama baru itu untuk tombol baru.

## Chat Gemini web (.gemini, internal/geminiapi)

Owner-only `.gemini` (alias `.gm`, `CategoryOwner`) adalah **chat Gemini lewat antarmuka web** dengan cookie akun Google khusus bot — bukan API resmi, bukan Chrome. Riwayat percakapan hidup di server Gemini; bot hanya menyimpan `data/gemini-cookie.txt` (kredensial, gitignored) dan pointer percakapan (`conv_id`/`resp_id`/`choice_id`) **di memori**, jadi mode otomatis nonaktif setelah restart. Tidak ada tabel/transkrip lokal: pesan sesi ini dikecualikan dari arsip CRM lewat `geminiPrivateMessage` (`plugins/crm.go` — command `.gemini`/`.gm` bisa memuat cookie) dan `MessageContext.SkipArchive` untuk semua balasan (jawaban, error).

Tanda "diterima" adalah **reaksi ✨** ke pesan prompt (`store.SendReaction`), yang berganti menjadi **⏳** setelah ±10 dtk (`geminiAckEscalate`) bila giliran belum selesai — `geminiEscalateAck` menunggu timer atau `turnDone` (ditutup setelah jawaban terkirim), jadi jawaban cepat tidak pernah meninggalkan ⏳. Keduanya reaksi, **bukan** pesan teks: jangan menghidupkan lagi bubble "sedang meneruskan ke Gemini…" (owner meminta chat bersih). Jawaban dirapikan `geminiCleanAnswer` (buang zero-width/`<ctrl…>`, lalu `ai.SanitizeForWhatsApp` — pembersih yang sama dengan flora agent: `**tebal**` → `*tebal*`, `---` dan heading Markdown dibersihkan); jangan kirim teks mentah dari parser. `.gemini on` sengaja **tidak** menampilkan baris `Cookie` (cukup Mode, Model, petunjuk); status cookie hanya di `.gemini status` dan `.gemini login`.

Subcommand (seluruh command hanya jalan di DM owner — `.gemini login <cookie>` di grup akan memampangkan cookie): `on` (aktifkan, cookie diperiksa dulu lewat GET `/app`), `off` (hapus sesi + pointer), `new` (buang pointer, mode tetap aktif), `login <cookie>` (simpan header `Cookie`; menerima satu baris, banyak baris, atau hanya nilai `__Secure-1PSID`; tidak pernah di-echo), `status` (mode, cookie, berkas, giliran, model), `diag` (lihat paragraf cookie di bawah; `diag upload` menguji jalur lampiran, `diag image` menguji generate + unduh gambar). Tanpa argumen = blok petunjuk. Prompt masuk lewat `gemini <teks>` (kata pemicu + spasi/`:`/`,`/`-`) atau **reply ke bubble bot** saat mode aktif (`plugins.CheckGeminiSession` dipanggil handler sebelum autodownload/AI, lalu memproses async). Lampiran gambar/PDF dari pesan atau reply ikut diunggah; gambar dinormalkan `seditPrepareImage`.

**Cookie setelah restart** (perbaikan "harus login tiap restart"): `__Secure-1PSIDTS` tetap disimpan ke berkas apa adanya (mungkin masih diterima Google), tapi tidak pernah dijadikan satu-satunya bukti. `Client.ensureMeta` berlapis: tembolok memori → tembolok disk `data/gemini-meta.json` (token `at`/`bl`/`f.sid`/push id, 0600, hanya dipakai bila umurnya < `metaTTL` 1 jam, ditulis setiap `/app` sukses, dihapus saat `sessionFingerprint` berubah = login ulang; `Ping`/`.gemini status` sengaja melewatinya supaya status benar-benar membuktikan cookie ke server) → GET `/app` dengan cookie lengkap → `rotate(force)` lalu `/app` sekali lagi → `/app` **tanpa cookie volatile** (`HeaderExcept(volatileCookieNames()...)`), karena TS basi kadang membuat Google menolak permintaan walau `__Secure-1PSID` sehat. Error asli baru dilaporkan setelah semua lapis gagal. Kegagalan menulis berkas cookie tidak lagi ditelan (`saveCookies` mencatat `saveErr` + log; `.gemini status` menampilkan `simpan gagal`). `geminiSessionProbe` tidak melabeli "ditolak" kalau rotasi gagal karena jaringan (label `tidak terverifikasi`). `.gemini diag` (`internal/geminiapi/diag.go`) menjalankan berkas → rotasi → tiga probe `/app` (cookie lengkap, tanpa TS, hanya `1PSID`) lalu menyimpulkan: TS bermasalah (bot mengulang tanpa TS) vs `1PSID` mati (harus login ulang); keluarannya hanya nama/status, tidak pernah nilai cookie.

Protokol (semua di `internal/geminiapi`): token halaman di-scrape dari `/app` — `SNlM0e` (`at`), `cfb2h` (`bl`; **label build pindah nama** dari `boq_assistant-bard-web-server_…` ke `boq_gemini-web-uiserver_…`, jadi ambil dari kunci `cfb2h`, bukan pola `boq_assistant`), `FdrFJe` (f.sid), `qKIAYe` (push id). `RotateCookies` (`POST https://accounts.google.com/RotateCookies`, body `[000,"-0000000000000000000"]`) memutar cookie pendamping tiap ±9 menit dan dipanggil sebelum ambil meta; hasil `Set-Cookie` diserap balik (atomik 0600) dan `MergeSetCookies` hanya menerima domain `google.com`. Chat = `POST /_/BardChatUi/data/assistant.lamda.BardFrontendService/StreamGenerate` dengan form `f.req` + `at`: array **97 slot** (slot 0 prompt + daftar lampiran, 2 pointer percakapan, 17 nomor giliran, 79 mode model [1 flash/3 pro/6 lite], 80 mode berpikir, 96 penanda giliran pertama). Balasan = deretan baris JSON; payload `wrb.fr` adalah string JSON bersarang yang harus di-parse lagi (teks kumulatif di `[4][*][1]`, pointer di `[1][0..1]` + `[4][0][0]`, gambar di `[4][0][12][7][0][i][0][3][3]` + `=s2048`). `BardErrorInfo` hanya dianggap error bila seluruh stream tak menghasilkan teks; kode `1096` = percakapan basi → plugin membuang pointer dan mencoba sekali lagi. Unggah lampiran memakai `content-push.googleapis.com/upload/` (OPTIONS → POST `start` → OPTIONS → POST `upload, finalize`, header `X-Tenant-Id: bard-storage`), batas 20 MB (`GEMINI_MAX_UPLOAD_MB`). **Tipe berkas wajib dideklarasikan**: `Upload(ctx, name, mime, data)` mengirim `X-Goog-Upload-Header-Content-Type` saat `start` dan memakai `mime` sebagai `Content-Type` saat `finalize` (mime kosong = `http.DetectContentType`); tanpa itu unggahan diterima tapi giliran chat bisa dijawab kosong. Gambar hasil (`lh3.googleusercontent.com/gg-dl/…`) sering menolak permintaan tanpa konteks browser (HTTP 403), jadi `Client.DownloadMedia` menjalankan **tangga percobaan** yang dicatat per rung: `sesi` (Cookie + UA + `Accept: image/*` + `Sec-Fetch-Dest/Mode/Site`, **tanpa `Origin`** karena browser tidak mengirimnya untuk `<img>`), `publik` (tanpa cookie), lalu `sesi-tanpa-ukuran` (buang sufiks `=sNNNN`) dan `sesi-s0`. Kalau semua rung HTTP gagal, rung terakhir **`chrome`** membuka URL yang sama di Chrome panel (Xvfb bila ada, fallback `--headless=new`) lalu mengambil gambar dari halaman yang sudah dimuat (kanvas → JPEG q0.95; `fetch` same-origin hanya cadangan). Cookie sesi **tidak** disuntikkan: permintaan gambar yang berhasil di browser owner tidak membawa header `Cookie`, jadi yang perlu direproduksi adalah konteks TLS/HTTP2 Chrome, bukan sesi Google. Rung Chrome hanya aktif untuk host `*.googleusercontent.com`/`*.usercontent.google.com` (host lokal di tes tidak boleh menyalakan browser), ditolak bila sisa memori cgroup <500 MB, dan profilnya di `gemini-profile/` (gitignored). `GEMINI_CHROME_PATH`/`GEMINI_XVFB_PATH`/`GEMINI_HEADED=0` hanya menimpa path/headless, bukan tuning. Tiap percobaan menyimpan status/content-type/ukuran + potongan body ≤160 rune; rung yang berhasil dicatat `media ok via <rung>`, kegagalan total menulis ringkasan `sesi 403; publik 403; …` plus snippet per rung (URL bertanda tangan tidak pernah masuk log/chat). Respons berstatus 200 tapi bukan gambar (halaman login) ditolak `isImageResponse`. Plugin **tidak boleh** menutupi error jalur sesi dengan error fallback: log mencatat sesi/umum/IPv4 terpisah dan pesan ke owner memakai error sesi. `.gemini diag image` (owner) meminta satu gambar, memindai **semua** URL media di payload (`Result.Candidates`, bukan hanya slot pertama; URL kanonik ditaruh paling depan) lalu melaporkan bentuk tiap kandidat + status tiap rung (termasuk `chrome` untuk kandidat pertama) + verdict (generasi vs 403 vs sehat); biayanya satu kuota generate. Semua kandidat URL **tidak** ditampilkan di chat, tetapi ditulis ke `wabot-tmp/gemini-image-url-<stamp>.txt` (0600) agar owner bisa mengujinya di HP: berhasil di incognito = URL publik dan penyebabnya IP/TLS panel; hanya berhasil saat login = gambar butuh cookie `googleusercontent.com`; gagal di keduanya = URL rusak/kedaluwarsa. URL dari stream dibersihkan `sanitizeMediaURL` (trim, `&amp;`→`&`, potong pada spasi/kuota/`<>)]}`/backtick, buang `.,;:` di ujung) karena satu karakter sisa markup membuat tanda tangan Google ditolak 403; `withSize` tidak menambah `=s2048` bila URL sudah memuat `=` atau `?`. `external.DownloadBytes`/IPv4 tetap jadi cadangan terakhir. Semua request `Chat` diserialkan (satu akun = satu stream) lewat mutex klien.

Model dipilih `GEMINI_MODEL_TEXT` (`lite` = generasi paling singkat; `flash`/`pro` untuk kualitas lebih tinggi), mode berpikir `GEMINI_THINKING=1`. Hanya `GEMINI_MODEL_TEXT`, `GEMINI_THINKING`, dan `GEMINI_MAX_UPLOAD_MB` yang dibaca dari env (plus `GEMINI_CHROME_PATH`/`GEMINI_XVFB_PATH`/`GEMINI_HEADED` yang hanya menimpa path/binary Chrome, pola sama dengan `.rch`); switch A/B dan diagnostik sengaja **dihapus** — jangan menambah env baru untuk tuning, ubah konstanta di `internal/geminiapi`. **Jangan kembalikan pembacaan stream ke `io.EOF`**: `parseStreamIdle` berhenti di penanda tutup `["e",4,…]` atau saat stream diam `defaultStreamIdle` (4 dtk) setelah ada jawaban, karena server Gemini sering menahan koneksi ±20 dtk setelah jawaban lengkap — itulah penyebab `.gemini` dulu terasa lambat (bukan generasi). Jeda panjang **sebelum** jawaban pertama tidak boleh dipotong (timer baru dipasang setelah teks/gambar ada). Perlu diketahui: setelah perbaikan ini sisa latensi di panel **bukan** dari bot — antrean server 8–20 dtk (tercermin di `Server-Timing dur`) sebelum bot menerima apa pun, ditambah ±12 dtk inferensi senyap, sedangkan generasi hanya 2–5 dtk; jangan mengejar angka itu dengan mengubah pembacaan stream lagi. Transport `internal/geminiapi/client.go` sengaja memaksa **IPv4** (`tcp4`) + keep-alive + `ResponseHeaderTimeout` 30 dtk: IPv6 di panel blackhole (connect menggantung ±15 dtk). Jawaban penolakan generik ("… hanya model bahasa …") berdurasi <10 dtk otomatis menyimpan payload mentah ke `wabot-tmp/gemini-raw-*.txt` (memuat isi percakapan: hapus manual setelah diperiksa). Jawaban **kosong** (tanpa teks/gambar, termasuk giliran ber-lampiran) menyimpan stream ke `wabot-tmp/gemini-empty-*.txt` — juga memuat isi percakapan — dan path-nya dicatat di log serta tersedia lewat `Client.LastDumpPath()`; `.gemini diag upload` (unggah PNG → satu giliran chat) menunjukkan apakah kegagalannya di unggah atau di chat ber-lampiran. Balasan panjang dipecah `geminiSplitReply` (potongan pertama me-reply perintah, sisanya pesan lepas); hasil gambar dikirim sebagai bubble gambar dengan caption teks + `Gemini · <model>` dan `> prompt`; kalau semua gambar gagal diunduh, plugin melapor "Gambar hasil Gemini (N) gagal diunduh" (bukan pesan kosong). Uji: `go test ./internal/geminiapi/` (parser, cookie, unggah, unduh media, dump — tanpa jaringan), lalu smoke live `GEMINI_SMOKE=1` (chat teks), `=2` (unggah gambar), `=3` (minta gambar), `=4` (dua giliran) — memakai cookie asli dan kuota akun. `GEMINI_DEBUG=1` menyimpan halaman `/app` ke `%TEMP%/gemini-app.html` untuk mendiagnosis perubahan skrip halaman.

## Voice note TTS (.tts / .vn / mode suara Flora — plugins/tts*.go)

Sintesis teks→MP3 lewat satu pintu `ttsSynthesizeMP3` (`plugins/tts.go`): **Edge Read Aloud dulu**, lalu **Google Translate TTS** sebagai cadangan (`plugins/tts_google.go`; matikan dengan `TTS_GOOGLE_FALLBACK=0`). `.tts`, `SynthesizeLong`, dan balasan suara AI semuanya lewat situ — jangan panggil `edgeTTSSynthesize` langsung dari plugin baru. Edge mewajibkan token `Sec-MS-GEC` **v2** (`<16 hex CS64>-<64 hex SHA256>`, port `drm.py` di `plugins/tts_gec.go`) dan `Sec-MS-GEC-Version` berawalan **`2-`**; v1 (SHA256 heks saja) dibalas `403 Invalid response status` sejak Okt 2026. Angka setelah awalan harus sama dengan versi Chromium di `ttsUA`. `ttsDialEdge` mengoreksi skew jam dari header `Date` lalu retry sekali (jam panel meleset juga bikin 403), dan error akhirnya memuat status + cuplikan body server. Fallback Google memecah teks ≤180 rune/request (endpoint tidak resmi, satu suara, tanpa pilihan karakter) dan menolak balasan non-MP3 — jaring pengaman, bukan pengganti. Tes: `go test ./plugins/ -run "TTS|GEC|Google"` (vektor token dihasilkan edge-tts 7.3.1), smoke live `TTS_SMOKE=1 go test ./plugins/ -run TestTTSSmoke -v`.

## Gotchas that bite

- Temp files: always `store.BotTempDir()` / `MustBotTempDir()` (`<workdir>/wabot-tmp`). Never `os.MkdirTemp`/`os.TempDir()` — panel `/tmp` is a 100 MB tmpfs, videos >~50 MB die with Errno 28. Jangan menulis artefak yang tidak dihapus sendiri: rekaman video call dulu memakai `AnnexBRecorder` ke `wabot-tmp/vcall-*.h264` dan tidak pernah dihapus (folder membengkak). Sisi terima video sekarang `videoCounter` (hitung frame/byte, tanpa file); `CleanStaleCallTemp()` menyapu sisa `vcall-*` saat startup.
- `data/` = session (`session.db`) + SQLite state (group/ai/facts/settings/finance/crm/absensi). Never delete, never commit (gitignored with `.env`, `wabot-go-linux`, `wabot-tmp/`). `scripts/push.ps1` warns on sensitive paths — heed it. `scripts/test-env.ps1` holds real secrets, stays uncommitted.
- Schema changes: each bot DB (`group/ai/finance/crm/absensi`) opens via `store.openSQLite` and applies schema through `store.applySchema` (`internal/store/schema.go`), which tracks `PRAGMA user_version` per file. When you add/alter a column, bump the matching `*SchemaVersion` const there and append the `ALTER` to the caller's slice. `ai.db` is one file shared by ai/facts/settings/summaries — the version const is per-file (`aiSchemaVersion`), not per table.
- Identity (owner name, bot name) is **compile-time** in `internal/config/config.go` — changing it needs rebuild + redeploy. `BotVersion` is a `var` injected at build time from the `VERSION` file via `-ldflags -X wabot-go/internal/config.BotVersion=...` (fallback = default in config.go); `scripts/deploy.ps1` auto-bumps it via `scripts/version-bump.ps1` to CalVer `v<bulan>.<tanggal>.<urut>` (tanggal deploy waktu lokal + urutan deploy hari itu), but only when code/tooling files changed since the last deploy (docs/data only = no bump; snapshot in gitignored `.last-deploy-state`). Provider/model choice is **runtime** in SQLite (`.agent` commands, no redeploy).
- WhatsApp identity is dual-format (LID vs phone number): never compare JIDs by raw string. Use `internal/identity` (the single source of truth: `Normalize`, `SameUser`, `Candidate.Matches`, `ResolvePN`/`ResolveLID`, `Keys`, `CanonicalUser`, `IsBot`) plus `store.ParticipantMatchesJID` / `IsSenderAdmin` / `IsBotAdmin` / `store.IsBotJID`. Owner/diagnostic: `.id` (owner) prints how the bot normalizes a sender/JID. A 1:1 DM can arrive as `@lid`, so detect private chat with `mctx.IsGroup()`, NOT `Chat.Server == "s.whatsapp.net"`.
- DB backups (`.backup` in `plugins/backup.go`): snapshot via `store.SnapshotDB` (`internal/store/snapshot.go`, SQLite `VACUUM INTO`) — never copy `data/*.db` directly, WAL make that inconsistent. Auto-backup schedule lives in `bot_settings` (`ownerdb.go`), result DM'd to `config.OwnerNumbers`; temp zips under `MustBotTempDir()` are always deleted after send.
- Keuangan bulanan (`plugins/finance_monthly.go` + `internal/finance/`): `data/finance.db` hanya menyimpan transaksi **bulan berjalan**. **Saat fitur pertama aktif** untuk seorang owner (belum ada baris `finance_periode`): SELURUH transaksi lama diarsipkan + dikirim ke DM owner, lalu buku dimulai ulang dari tanggal aktivasi dengan saldo awal = net transaksi lama (`ResetFinanceOwnerInitial`, satu transaksi atomik). Setelah itu, saat pergantian bulan sweep menutup periode: rakit laporan Excel → arsip di `data/arsip-keuangan/<YYYY>/` → kirim DM owner → bawa saldo akhir ke saldo awal bulan berikutnya (`finance_periode`) → HAPUS transaksi bulan itu. Pemicu = timer ke awal bulan + catch-up startup (bukan polling); gagal = ulang tiap 30 menit. Kolom `input_at` (waktu input) **beda** dari `tanggal` (waktu transaksi, bisa backdate); baris lama `input_at` kosong. `rekap_keuangan` rentang terbuka = saldo bulan berjalan (termasuk saldo awal).
- Zona waktu: satu-satunya sumber `internal/timex` (`Zone`/`Name`/`Now`/`Today`). `BOT_TIMEZONE` memakai nama IANA (mis. `Asia/Makassar`); alias lama `WIB`/`WITA`/`WIT` tetap diterima, kosong = `Asia/Makassar`, nilai asing = fallback + warning. `time/tzdata` di-embed jadi tidak bergantung `/usr/share/zoneinfo` container, dan nilai dibaca sekali per proses (ubah `.env` → restart). **Jangan pakai `time.Local` untuk menampilkan jam** — panel berjalan di UTC; `Name()` mengembalikan label pendek (`WIB`/`WITA`/`WIT`, atau singkatan zona lain) yang dipakai di teks owner.
- README claims `run.sh` sources `.env`, but current `run.sh` does not - trust the script, not the prose; ensure env reaches the process via the panel environment.

## Database user (.userdb / .udb / internal/userdir)

Direktori identitas user per grup, diisi **manual** (tidak ada hook pesan/startup) supaya bot tidak terbebani. Tiga lapisan: `data/users.db` (identitas global: LID/PN/JID/pushname/nama kontak/status foto), `group_members` di `group.db` (roster per grup, ikut per-clone lewat `GroupsFor`), dan cache foto `data/pp/<sha>.jpg` (JPEG ≤640 q85). Command owner-only: `.userdb sync|syncpp|status|info|stats|prune` (alias `.udb`). Target: ID grup (lihat `.listgrup`, permanen), `@mention`, reply, nomor HP, atau JID. `.listgrup` menampilkan ID permanen `[001] Nama` (tabel `group_ids`, `groupSchemaVersion` 2→3). `sync` grup = identitas semua member; `syncpp` = sekaligus foto (async, ringkasan dikirim ke chat asal command, bukan grup target). `sync <user>` = satu user via `GetUserInfo` + contacts. `info <user>` = bubble foto + caption, menolak user yang belum disync. `users.db` init fail-soft. Skema: `usersSchemaVersion=1`. SPR/SBPR **belum** memakai DB ini (fase berikutnya).

## SPR / SBPR (plugins/spr.go, plugins/sbpr.go)

Owner-only, **hanya via chat private ke bot** (ditolak di grup); eksekusi tetap di grup target yang ditentukan dengan **ID grup dari `.listgrup`** (bukan JID mentah). Target pesan memakai **nomor telepon** (`628...` atau `+62 8...`), dinormalisasi ke PN/LID. `.spr`: `.spr <id grup> <nomor...> <pesan> [| decoy]`, `.spr <id grup> debug`. `.sbpr`: `.sbpr <id grup> <nomor...> <teks>`, `sapa`, `getpp`, `status`, `profile`. Batch/progres async; ringkasan dikirim ke chat asal command. Jangan hidupkan kembali `-g`/target `@mention` lama. Audit fase A diterapkan: lock+snapshot `perSender`, retry diserialkan, kunci per grup + reset segera, `.spr` async, satu bubble multi-target, target LID+PN, reset memakai LID (gagal jelas bila kosong), tolak grup komunitas, fallback tidak bocor, preserve `DeviceSentMessage`, prune berbasis waktu.

## Deploy (laptop → Pterodactyl panel)

Source lives only on the laptop; the panel gets just the binary. Order: stop bot in panel → `.\scripts\deploy.ps1` (`-y` skips prompt) → start bot. `.\scripts\build.ps1` builds the same binary **without** uploading (for manual File Manager upload); `-Keep` builds with the current `VERSION` and leaves `VERSION`/`.last-deploy-state` untouched, plain run bumps CalVer like deploy does. It builds `GOOS=linux GOARCH=amd64 go build -o wabot-go-linux .` then `rclone copyto` to remote `panel:/` with `--inplace` (panel SFTP rejects rename) and verifies remote size. `greeting.mp3`/`.env` are uploaded separately, not via deploy.
